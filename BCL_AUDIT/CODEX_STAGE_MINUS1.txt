B2. CIFAR ResNet-32
- Implement the standard CIFAR ResNet-32, not an ImageNet ResNet-32:
  3x3 stem, 16 channels, three residual stages with [5,5,5] BasicBlocks,
  stage widths 16/32/64, downsampling at stages 2 and 3, global average pooling,
  64-dimensional final feature.
- Verify depth and output shapes with a unit test.
- Use the CIFAR shortcut convention from the referenced PaCo CIFAR ResNet-32
  implementation (Option A) unless an exact equivalent implementation already
  exists in this new package.
- Classifier for this CIFAR port: standard nn.Linear(64,100), not the BCL
  ImageNet NormedLinear(s=30). The inspected BCL paper/code does not establish
  that s=30 is used for CIFAR. Record this implementation choice in the report.
- Do not add an extra classifier scale or temperature.

B3. BCL architecture
Implement the shared-backbone, two-branch graph:
  v1 -> shared ResNet32 -> classifier W -> LC
  v2,v3 -> shared ResNet32 -> sample projection MLP -> normalized z2,z3 -> BCL
  W -> separate prototype MLP -> normalized class prototypes -> BCL

For ResNet-32 feature dimension 64:
  sample MLP: Linear(64,512) -> BatchNorm1d(512) -> ReLU -> Linear(512,128)
  prototype MLP: a SEPARATE MLP with the same dimensions
  L2-normalize sample embeddings and prototype embeddings before BCL.

The classifier weight matrix for nn.Linear has shape [100,64]. Feed its 100
class rows through the prototype MLP to obtain [100,128] prototypes.

Important gradient-graph rule:
- shared parameters that receive both LC and BCL gradients: Backbone and W.
- sample projection MLP: BCL gradient only.
- prototype MLP: BCL gradient only; it maps BCL gradients back to W.
Do NOT treat the prototype MLP as a third cross-branch gradient-conflict site.

For paired initialization, instantiate the same full model/module order for both
groups, save one initial state, and reload that same initial state before each run.
This guarantees identical initial backbone/classifier weights and a consistent
initialization protocol. The LC-only run simply does not execute the contrastive
path/loss. Do not create different backbone/classifier initializations by accident.

B4. BCL loss
- Implement the official released BalSCL / BCL formula faithfully:
  class-complement prototypes are appended to the two contrastive-view embeddings;
  positives include same-class view embeddings and the class prototype;
  denominator contributions are averaged by class (class-averaging).
- Temperature tau=0.1.
- Use the released official BCL loss implementation as the semantic reference:
  https://github.com/FlamieZhu/Balanced-Contrastive-Learning/blob/main/loss/contrastive.py
- You may reimplement the operations with device-safe, readable PyTorch code.
  If you copy any source code, preserve its attribution/license.
- Add tests for output scalar, finite loss, finite gradients, correct positive masks,
  and all 100 prototypes being included in every BCL denominator.
- Avoid accidental CPU tensors in the loss (e.g. torch.eye created on CPU then
  indexed on CUDA). Every mask/count tensor must be created on the active device.

B5. Logit compensation and total objective
For class counts n_y:
  prior_y = n_y / sum(n)
  adjusted_logits = logits_v1 + log(prior_y)
  LC = cross_entropy(adjusted_logits, labels)

Use:
  Group A (LC-only): total_loss = 2.0 * LC
  Group B (BCL):     total_loss = 2.0 * LC + 0.6 * BCL

Only v1 logits contribute to LC. BCL uses only v2 and v3 sample embeddings plus
the classifier-derived prototypes.

C. VIEW AUGMENTATIONS AND BN SEMANTICS
--------------------------------------
Use the CIFAR-specific transformations in the protocol audit:

v1 classification view:
  RandomCrop(32, padding=4)
  RandomHorizontalFlip
  CIFAR AutoAugment policy
  ToTensor
  Cutout(length=16)
  Normalize(mean=(0.4914,0.4822,0.4465), std=(0.2023,0.1994,0.2010))

v2 and v3 contrastive views, independently sampled:
  RandomResizedCrop(32, scale=(0.2,1.0))
  RandomHorizontalFlip
  ColorJitter(0.4,0.4,0.4,0.1), p=0.8
  RandomGrayscale(p=0.2)
  GaussianBlur with sigma range [0.1,2.0], p=0.5
  ToTensor
  same CIFAR normalization

Use the CIFAR AutoAugment / Cutout and SimAugment semantics from the referenced
PaCo CIFAR implementation where needed:
  https://github.com/JIA-Lab-research/Parametric-Contrastive-Learning
  PaCo/LT/paco_cifar.py
If copying a helper, preserve its license/attribution. Do not replace CIFAR AutoAugment
with RandAugment. Do not invent a different SimAugment pipeline without documenting it.

BCL forward:
- For each batch, concatenate [v1, v2, v3] along batch dimension and pass the
  concatenated tensor through the shared ResNet-32 in one forward call.
- Split outputs back into three B-sized chunks.
- Use v1 logits for LC and v2/v3 embeddings for BCL.
- This intentionally reproduces the three-view BatchNorm semantics of the BCL
  implementation: backbone BatchNorm2d statistics mix v1 AutoAugment and v2/v3
  SimAugment distributions.
- The sample projection MLP is also applied to all 3B features before z2/z3 are
  selected; its BatchNorm1d therefore mixes all three views as well.
- Although BCL loss directly consumes only z2/z3, train-mode BatchNorm coupling
  can send BCL gradients indirectly to v1 backbone feature rows. This is a
  view-level coupling, not a third shared trainable-parameter conflict site.
- LC-only Group A must use only v1 in the first pilot.
- Record both BN differences between A and B. Do not add a BN-matched control or
  another experiment group in this task.

D. TRAINING PROTOCOL — ONLY ONE SEED, 200 EPOCHS
-----------------------------------------------
Run the two groups sequentially, not concurrently:

  Group A: LC-only, one view, seed=42, 200 epochs
  Group B: BCL, three views, seed=42, 200 epochs

Shared settings:
- batch size 256
- FP32 only; no autocast / AMP
- no gradient accumulation
- SGD, momentum=0.9
- base LR=0.15
- weight decay=5e-4
- 5-epoch linear warmup from 0 to 0.15
- multiply LR by 0.1 after 160 completed epochs and after 180 completed epochs
- total 200 epochs
- DataLoader shuffle generator and worker seeds must be explicitly set
- reset Python / NumPy / torch / CUDA RNGs before each group
- use the same saved initial backbone/classifier weights for both groups
- use the exact same saved IF=100 sample indices

Use 0-based epoch indices internally. Warmup covers epoch indices 0..4. Apply the
first LR drop at the start of epoch index 160 (after 160 epochs are complete), and
the second at the start of epoch index 180.

Checkpoint milestones (human-numbered completed epochs):
  epoch_040
  epoch_100
  epoch_160_pre_decay
  epoch_180_pre_decay
  epoch_200

The epoch_160_pre_decay checkpoint is saved immediately after completing the
160th epoch and before the LR drop used for epoch 161. The epoch_180_pre_decay
checkpoint is saved immediately after completing the 180th epoch and before the
LR drop used for epoch 181.

Record per epoch:

- LC and BCL losses separately (BCL loss is absent/zero for Group A)
- training accuracy
- epoch wall-clock seconds
- CUDA peak allocated memory (reset / record clearly)
- checkpoint path and best/final status

Do not choose checkpoints by test accuracy. Use the final epoch-200 checkpoint
for the first pilot's headline evaluation.
