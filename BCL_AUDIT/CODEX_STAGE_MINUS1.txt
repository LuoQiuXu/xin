B. REVIEW AND TEST THE EXISTING CIFAR PORT
------------------------------------------
The package already exists. Do not overwrite it blindly.

B1. CIFAR-100-LT split
- Original CIFAR-100 train split only.
- Official fine-label order 0..99; do not shuffle class order.
- Exact count rule:
    n_i = int(500 * 0.01 ** (i / 99.0)), i=0,...,99
- Use int() truncation, never round().
- IF=100 expected endpoints: 500 and 5.
- Expected total: 10,847 images.
- split_seed=0 selects original training indices within each class.
- training seed=42 is separate from split_seed=0.
- Use the exact same saved indices in LC-only and BCL.
- Validate no duplicate/out-of-range indices and exact class-count vector.
- Validate 100 fine classes, 20 CIFAR-100 coarse superclasses, exactly five
  fine classes per coarse superclass.

B2. CIFAR ResNet-32 / classifier
- CIFAR ResNet-32: 3x3 stem, [5,5,5] BasicBlocks, widths 16/32/64,
  Option-A shortcut, final feature dimension 64.
- Standard nn.Linear(64,100) classifier.
- Do NOT import the ImageNet BCL NormedLinear scale s=30 into CIFAR.
- The inspected official BCL public entry point is for ImageNet/iNaturalist;
  it does not provide a wired CIFAR-100 training route.
- Record that this is a standalone paper-faithful CIFAR port, not an
  unmodified official CIFAR entry point.

B3. BCL graph and loss
- Shared ResNet-32 backbone.
- v1 -> backbone -> W -> logit-compensated CE.
- v2/v3 -> backbone -> sample MLP -> normalized embeddings -> BCL.
- W -> separate prototype MLP -> normalized class prototypes -> BCL.
- Sample and prototype MLPs are separate 64->512->128 MLPs.
- The prototype MLP is a differentiable mapping from W to class prototypes;
  it is not an independent cross-branch conflict site.
- Shared parameters receiving LC and BCL gradients: backbone and W.
- Use the device-safe BalSCL/BCL formula with class-complement prototypes and
  class-averaging. Temperature=0.1.
- Logit compensation: logits + log(class_prior).
- LC-only objective: 2.0 * LC.
- BCL objective: 2.0 * LC + 0.6 * BCL.

C. MATCHED THREE-VIEW PAIRED CONTROL — CRITICAL
------------------------------------------------
Both groups MUST use the same three-view data protocol:

- v1: RandomCrop(32,padding=4), RandomHorizontalFlip, CIFAR AutoAugment,
  ToTensor, Cutout(length=16), CIFAR-100 normalization.
- v2 and v3: independently sampled SimAugment views:
  RandomResizedCrop(32,scale=(0.2,1.0)), HorizontalFlip, ColorJitter,
  Grayscale, GaussianBlur, ToTensor, CIFAR-100 normalization.

For BOTH LC-only and BCL:
1. Concatenate [v1,v2,v3] into one 3B tensor.
2. Pass the 3B tensor through the shared backbone in one forward call.
3. Use only the first B v1 logits for the LC objective.

Additional BCL operations:
- Apply the sample MLP to all 3B backbone features.
- Use only v2/v3 embeddings in the BCL sample term.
- Derive all class prototypes from classifier rows W through the separate
  prototype MLP.

LC-only must NOT revert to a one-view backbone forward. This matched protocol
is required so backbone BatchNorm2d sees the same three-view input mixture in
both groups.

Record the remaining branch-specific BN distinction:
- BCL's sample projection MLP has BatchNorm1d and is applied to all 3B
  features; LC-only does not execute this projection MLP.
- Do not mislabel this BN/view coupling as a third shared parameter-conflict
  site.
- batchnorm_audit.jsonl must record first-minibatch per-view input moments
  and BN running-stat summaries at epochs 40/100/160/180/200.

D. FIXED TRAINING PROTOCOL — ONE SEED ONLY
------------------------------------------
Run groups sequentially, not concurrently:

  Group A: LC-only, three-view concatenated backbone, LC on v1 only.
  Group B: original BCL, same three-view backbone, LC on v1 plus BCL on v2/v3.

Shared settings:
- seed=42 for both groups
- same saved initial full model state for both groups
- same exact IF=100 sample indices
- batch size=256
- FP32 only; no AMP/autocast
- no gradient accumulation
- SGD, momentum=0.9
- base LR=0.15
- weight decay=5e-4
- 5-epoch linear warmup from 0 to 0.15
- LR drops by 0.1 at the start of epoch index 160 and epoch index 180
  (after 160 and 180 completed epochs)
- 200 epochs total
- DataLoader shuffle generator and worker seeds explicitly set
- reset Python / NumPy / torch / CUDA RNGs before each group

Checkpoint milestones (human-numbered completed epochs):
  epoch_040.pth
  epoch_100.pth
  epoch_160_pre_decay.pth
  epoch_180_pre_decay.pth
  epoch_200.pth

Each checkpoint must include model state (including BN running buffers),
optimizer state, RNG states, epoch, group, seed, class counts, and protocol.
Epoch 160 and 180 checkpoints must be saved after those epochs complete and
before the next epoch's LR decay.

Record per epoch:
- LR, LC loss, BCL loss (zero/absent for LC-only), total loss
- raw-logit training accuracy
- epoch wall-clock seconds
- peak allocated CUDA memory
- checkpoint path at milestone epochs

If batch 256 FP32 OOMs, STOP and report the exact trace and memory usage.
Do not silently reduce batch size, enable AMP, or add gradient accumulation.

G. ONE MERGED OFFLINE DIAGNOSTIC PASS
-------------------------------------
After both final evaluations are saved, run:

  python -m BCL_AUDIT.scripts.analyze_paired_bcl --data-root "<actual CIFAR root>" --indices-file "BCL_AUDIT/outputs/data_audit/cifar100lt_if100_train_indices_seed0.npy" --output-root "BCL_AUDIT/outputs" --probe-per-class 5 --probe-seed 777 --batch-size 128

This is the merged offline pass; do not create a separate training stage.

G1. Fixed probe
- Select five examples per fine class from the saved LT training indices.
- Cache v1/v2/v3 and deterministic evaluation views once.
- Reuse exactly the same 500 probe images/views for every checkpoint.
- This probe is sourced only from the LT training subset; no test data.

G2. Checkpoint margins
- For LC-only and BCL checkpoints 40/100/160/180/200:
  report per-class probe accuracy, raw true-class margin, and
  logit-adjusted true-class margin.

G3. Dual-layer gradient diagnostics
- Run on BCL checkpoints only; LC-only projection heads are untrained.
- Put the model in eval mode to freeze BN running statistics.
- Use the same v2 feature tensor f(x) for both LC and BCL gradient calculations.
- LC: classifier W and logit-compensated CE.
- BCL: same f(x) through sample MLP, paired with v3, plus classifier W through
  prototype MLP.
- At classifier row W_y report cosine(grad_W_y LC, grad_W_y BCL), both norms,
  and norm ratio.
- At the same probe feature f(x), report cosine(grad_f LC, grad_f BCL), both
  norms, and negative-cosine fraction.
- Do not count prototype MLP as a separate conflict site.
- State clearly that eval-mode probes isolate local loss gradients; train-mode
  BN coupling is measured separately by batchnorm_audit.jsonl.

G4. Head-Tail directional confusion / paired DID
- Use only saved final epoch-200 benchmark predictions/logits.
- For each directed pair:
    C[a->b]^M = P(prediction=b | true=a, model=M)
    Delta C[a->b] = C[a->b]^BCL - C[a->b]^LC-only
- Report Head->Tail and Tail->Head separately.
- Group pairs by the exogenous CIFAR-100 coarse-superclass label and compute:
    DID = E[Delta C | SameSuperclass]
          - E[Delta C | DifferentSuperclass]
- Also report pairwise raw-logit and adjusted-logit margins.
- If DINO Top-K union is present, report it as a separate relation slice.
- Report pair counts. One-seed DID is descriptive, not seed-level significance.

H. ORACLE GATE — DO NOT RUN NOW
--------------------------------
No Oracle in this task. The first paired seed is reconnaissance only.

Only after additional paired seeds show repeatable and coherent evidence across
gradient direction/norm, margins, directional confusion, and Overall/Many/
Medium/Few performance may one mechanism-aligned Oracle be selected:

1. Prototype Oracle: replace W-derived prototypes with balanced reference
   feature prototypes.
2. Relation Oracle: suppress/down-weight same-superclass negative prototypes
   in the contrastive denominator.
3. Gradient Oracle: remove only the BCL gradient component conflicting with LC:
   g_BCL* = g_BCL - min(0, g_LC^T g_BCL) /
            (||g_LC||^2 + eps) * g_LC.
   Test classifier-W and backbone scopes separately if justified.

Do not run all three as a fishing expedition. Stop if the selected Oracle has
no stable benefit or improves one class group only by sacrificing another.
No numeric go/no-go threshold was pre-registered; do not invent one after
seeing the results.
