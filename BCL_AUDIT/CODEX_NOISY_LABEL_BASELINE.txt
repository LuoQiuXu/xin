MISSION
-------
Implement and execute the FIRST CONTROLLED LABEL-NOISE BASELINE for original
BCL on CIFAR-100-LT IF=100. The purpose is only to measure how standard BCL
degrades under known synthetic label corruption. Do NOT implement any
anti-noise method yet.

Conditions:
  A. Clean labels (0% noise)
  B. Symmetric label noise (20%)
  C. Symmetric label noise (40%)

Use the existing audited BCL CIFAR port, ResNet-32, the exact fixed IF=100
training indices, three-view pipeline, BCL objective and evaluation protocol.
This is a new experiment branch. Do not work on main or overwrite the parent
branch.

IMPORTANT EXPERIMENT DESIGN
---------------------------
1. Preserve the LT subset first. Use the exact preflight-generated indices
   file (10,847 rows, class counts 500 -> 5) unchanged for all three groups.
2. Corrupt ONLY labels attached to those selected training examples. Do not
   alter images, sample indices, class selection, test labels, or test images.
3. Noise is instance-independent symmetric K-class noise:
   - choose exactly round(rate * 10,847) selected examples without replacement;
   - each selected label is replaced uniformly by one of the other 99 classes;
   - never select the original class as the replacement;
   - input/sample order is preserved.
4. Generate each corruption once from the clean labels and fixed seed 2026.
   Save clean labels, noisy labels, flipped mask, selected original indices,
   requested/realized rate, transition counts, clean/noisy class counts,
   seed, and SHA-256 checksums in a compact noise_manifest.npz/json.
   The corruption must be deterministic and independent of training seed.
5. The clean condition must use the original labels byte-for-byte.
6. BCL class averaging and LC log-prior must use the OBSERVED noisy-label
   class counts in 20%/40% groups, because these are the labels available to
   the learner. Do not use latent clean labels for training losses, sampling,
   class counts, early stopping, checkpoint selection, or tuning.
7. Keep clean labels ONLY for offline corruption auditing and reporting:
   flipped count/rate, per-source-class flips, source->observed transition
   matrix, and verification. Never feed clean labels into model/loss code.
8. Evaluation uses the original balanced CIFAR-100 TEST split with its clean
   ground-truth labels. Evaluate raw logits and the same logit-compensated
   logits convention used by the existing BCL audit; clearly label both.
   Do not use test data for training, noise generation, checkpoint selection,
   or hyperparameter tuning.

TRAINING PROTOCOL
-----------------
- BCL only (no LC-only group in this first noise sensitivity screen).
- 200 epochs, seed 42, batch 256, FP32, no AMP, no TF32, no gradient
  accumulation, SGD momentum 0.9.
- Base LR 0.15, weight decay 5e-4, 5-epoch warmup, drops after 160 and
  180 completed epochs.
- Objective: 2.0 * LC + 0.6 * BCL; temperature 0.1.
- CIFAR ResNet-32 and standard nn.Linear(64,100), no ImageNet s=30 scale.
- Identical model initialization across the three conditions: save one
  initialization state and reload it for every condition.
- Use identical epoch seeds, DataLoader generator seeds, sample order and
  three-view augmentation RNG stream across conditions. The label corruption
  must not consume or perturb the Python/NumPy/Torch RNG streams used for
  model init or augmentations. Precompute labels before training.
- Run conditions sequentially to fit the 8 GB GPU. Do not run concurrently.
- If the existing 200-epoch clean BCL checkpoint from the approved parent
  Stage -1 experiment is available locally AND its source/data/protocol hashes
  match, it may be reused as the clean condition. Otherwise train clean.
- Never silently change batch size, precision, model, augmentation, epochs,
  or optimizer to make the run fit. If batch 256 FP32 OOMs, stop and report.

   - all selected original indices are unique and exactly match saved IF=100;
   - clean counts exactly equal IF=100 counts;
   - exact requested flip count;

   Report:
   - Overall top-1;
   - Many/Medium/Few macro-class top-1 using CLEAN LT class-count groups;
   - raw-logit and logit-compensated top-1 (separate);

J. Run the three conditions sequentially. After each run, verify checkpoints
