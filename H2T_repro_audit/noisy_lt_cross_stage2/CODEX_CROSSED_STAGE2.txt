## 最小科学设计：只补缺失的交叉单元
2x2 因素：
- Factor R = Stage I backbone+初始classifier来源（clean/noisy）。
- Factor S = Stage II训练时观测标签与balanced receiver样本池（clean/noisy）。
已有R=clean,S=clean，R=noisy,S=noisy；**仅补**：
1. R=clean，S=noisy；
2. R=noisy，S=clean。
每个交叉单元StageII seeds124/125、NoFusion/H2T各一，共**8个10epoch Stage II**；没有Stage I训练。保留作者ResNet32、随机16/64通道替换(rho .25)、class-balanced receiver/instance donor、BN-shift、CE、10epoch、同源FC初始化及原始optim/scheduler，固定最后epoch。
- 此对照是机制归因的**诊断性反事实**。R=clean或S=clean使用可信干净训练标签，是上界，不得声称实际部署的noise-robust算法。
- StageII噪声标签变化也改变观测类别频次及采样，故S因素是【observed label + sampling regime】的整体条件，不是只改loss的纯因果隔离。
- 两个StageII seed共享一份StageI来源，不能将其视作独立StageI重复。

## 执行
1. git checkout experiment/noisy-h2t-crossed-stage2-20261029；核对source目录存在：
   - SOURCE/primary_cache/stage1_clean/epoch200.pth
   - SOURCE/primary_cache/stage1_noisy/epoch200.pth
   - SOURCE/primary_cache/inputs/validation_images.npy
   - SOURCE/protocol/clean_train.npz + noisy_train.npz + clean_validation.npz
   - 对照SOURCE/stage1_{regime}/RUN.json中权重SHA。
2. CPU静态、最小纯分析单元测试：
   `python -m unittest discover -s H2T_repro_audit/noisy_lt_cross_stage2 -p "test_*.py" -v`
   `python -m py_compile H2T_repro_audit/noisy_lt_cross_stage2/*.py`（PowerShell通配符若不能按预期展开则用compileall）
3. 先执行已实现的真实单batch `--dryrun`：`python H2T_repro_audit/noisy_lt_cross_stage2/cross_stage2.py train --representation clean --labels noisy --seed 124 --method no_fusion --dryrun`，随后相同参数把method改为h2t。检查每臂1次更新、相同BN状态和mask/受体/供体配对。两次dryrun产物在独立dryrun_*目录，不作为正式模型；出现错误仅修复本轮文件并写入报告。
4. 正式运行时，每个cross cell+seed必须先NoFusion再H2T，让H2T从NoFusion的850批预更新审计记录配对；若配对或BN不一致应停止，不得改成近似容忍。
   ```powershell
   $script = "H2T_repro_audit/noisy_lt_cross_stage2/cross_stage2.py"
   foreach ($pair in @(@("clean","noisy"),@("noisy","clean"))) {
     foreach ($seed in @(124,125)) {
       python $script train --representation $pair[0] --labels $pair[1] --seed $seed --method no_fusion
       if ($LASTEXITCODE -ne 0) { throw "NoFusion failed" }
       python $script train --representation $pair[0] --labels $pair[1] --seed $seed --method h2t
       if ($LASTEXITCODE -ne 0) { throw "H2T failed" }
     }
   }
   ```
5. 全8个模型训练结束且SHA固定后，再允许一次性读取已有TRAIN holdout数据执行：
   ```
   python H2T_repro_audit/noisy_lt_cross_stage2/cross_stage2.py evaluate
   python H2T_repro_audit/noisy_lt_cross_stage2/analyze_factorial.py --diagonal H2T_repro_audit/noisy_lt_failure_screen/results/cifar100n_lt_seed42_20261029_01/evaluation/final_metrics.csv --crossed H2T_repro_audit/noisy_lt_cross_stage2/results/cross_stage2_01/crossed_final_metrics.csv --output H2T_repro_audit/noisy_lt_cross_stage2/results/cross_stage2_01/analysis
   ```
6. 报告`CROSSED_STAGE2_SCIENTIFIC_REPORT.md`必须给出全部4个R×S单元上的Few/Overall和其他频组H2T−DR相对收益（每seed和均值）；解释主要效应：
   R-effect = 1/2[(D_noisy,clean−D_clean,clean)+(D_noisy,noisy−D_clean,noisy)]
   S-effect = 1/2[(D_clean,noisy−D_clean,clean)+(D_noisy,noisy−D_noisy,clean)]
   interaction = D_noisy,noisy−D_noisy,clean−D_clean,noisy+D_clean,clean。
   请报告per seed，不要只挑均值；既有Clean/Noisy两端数据和当前新8组需使用同一验证集、同一class group。
7. 报告标记以下科学意义：
   - 若R干净、S噪声就使H2T的Few收益明显衰减，而且两个seed同向，StageII noisy supervision/sampler有独立证据，下一轮允许一个最小**类别感知的接收者可靠性/融合监督**模块，与DR及原H2T直接比较；不要先泛化成“所有noisy增强有害”。
   - 若R噪声、S干净仍不能恢复收益，而R干净、S噪声保留收益，表示StageI受噪声表征是主要候选问题。未来可组合现有RoLT/H2E等noise-robust表示方法，而不是强行改donor。
   - 若二者协同、交互强，明确提出“联合效应”，下一轮也只挑一个可测子问题，不进行一大批ablation。
   - 若新结果互相矛盾或变化非常小，不要强行归因；封存该局部假设即可，但**不等于整个噪声长尾研究方向无价值**。
8. 新结果仅为Clean TRAIN holdout的开发集，class0不存在；不能利用官方TEST选模，也不能和论文官方Few定义混为一谈。不得用分类器或测试集预测修正训练标签。
