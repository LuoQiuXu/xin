必须用代码逐项确认当前生产 A 和 Autograd B 的真实计算路径：

A 当前解析路径：
1. logits_clean.detach().softmax(dim=1)
2. p-one_hot
3. (p-one_hot) @ classifier_weight
4. 对 class mask 取 compact [n_c,64] 梯度
5. 在 compact 梯度上做 L2 norm
6. 除以 norm，再乘 class_weight 和 ADVER_REG

B 参考路径：
1. classifier_fc(z)
2. F.cross_entropy(logits, labels, reduction="none")
3. 对每个类别调用 torch.autograd.grad(losses[mask].mean(), z)
4. 得到完整 [B,64] 梯度（非本类样本位置为零）
5. 在完整 [B,64] 张量上做 L2 norm
6. 用本类对应位置生成 delta

确认类别计数 n_c>1 时，mean backward 的缩放顺序。用只读的 autograd.grad(losses[mask].mean(), logits) 捕获实际 logits 梯度，不能只靠公式推测。

## 4. 实现前的数值候选矩阵（只读，不写生产代码）

以第四轮完全相同的 seed123/epoch0/batch0 数据、特征、分类头、类别权重重放，保留 A/B，并至少比较以下候选：

- A：原生产实现。
- B：原 autograd_reference_delta，作为唯一 oracle。
- C：只把概率改为 F.log_softmax(logits.detach(),dim=1).exp()。
- D：只把 class norm 的输入改成完整 [B,64] 零填充张量。
- E：只把 class_count 的除法移动到 (p-y) 与 W 矩阵乘法之前。
- F：log_softmax.exp + class_count 预缩放 + 完整 [B,64] norm，作为优先候选。
- G/H：若 F 未通过，分别测试 count 缩放采用除法与乘 reciprocal 两种 FP32 操作顺序；必须保留中间张量，不得暗中混合多项改动。

候选 F 的数学结构如下（这是待验证候选，不是预先认定的最终答案）：

~~~python
log_prob = F.log_softmax(logits_clean.detach(), dim=1)
probabilities = log_prob.exp()
one_hot = F.one_hot(labels, num_classes=NUM_CLASSES).to(probabilities.dtype)
logit_gradient = probabilities - one_hot

counts = torch.bincount(labels, minlength=NUM_CLASSES)
sample_counts = counts[labels].to(logit_gradient.dtype).unsqueeze(1)
scaled_logit_gradient = logit_gradient / sample_counts
per_sample_gradient = scaled_logit_gradient @ classifier_weight.detach()

delta = torch.zeros_like(gap)
for class_id in torch.unique(labels, sorted=True):
    mask = labels == class_id
    class_gradient_full = per_sample_gradient * mask.unsqueeze(1).to(per_sample_gradient.dtype)
    class_norm = torch.linalg.vector_norm(class_gradient_full)
    if class_norm > 1e-12:
        delta[mask] = (
            ADVER_REG * class_weights[class_id]
            * class_gradient_full[mask] / class_norm
        )
~~~

重点：候选 F 将 1/n_c 放到矩阵乘法之前；norm 输入与 Autograd 保持完整 [B,64] 形状。必须通过 autograd 实测确认，不得仅凭数学等价宣告正确。

如果 F 不通过，先比较捕获的 logits gradient、feature gradient、norm、direction、delta，定位第一个出现超容差的阶段，再只调整对应的 FP32 运算顺序。不得同时改变无关模块。

每个候选、每个阶段都记录：
- finite / NaN / Inf；
- max_abs；
- max_relative（分母 max(abs(reference),1e-12)）；
- max_normalized_error = max(abs(error)/(1e-7+1e-5*abs(reference)))；
- 超容差元素数；
- torch.allclose；
- byte_equal；
- 最坏元素的 class_id、batch_position、TRAIN index、feature dimension、candidate/reference/error/allowed_error；
- 每个类别的 n_c、class norm、class weight。

阶段至少包括：
1. probability；
2. logits gradient；
3. raw feature gradient；
4. class-averaged full feature gradient；
5. class norm；
6. normalized direction；
7. final delta。

禁止只报告 max_abs 而不报告逐元素容差违规数。
