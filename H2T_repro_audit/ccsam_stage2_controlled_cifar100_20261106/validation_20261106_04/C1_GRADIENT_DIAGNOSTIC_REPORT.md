# C1 真实批次梯度等价性诊断

本轮完成只读诊断，**未修改生产实现，原 C1 门禁仍然失败，未重跑 Smoke 或启动训练**。

## 结论与证据等级

**本次真实批次的失败原因已定位到 FP32 数值计算路径不一致。** 生产解析实现使用独立 `softmax`，而本次实际 CrossEntropy Autograd 图保存的是 `LogSoftmaxBackward0` 的输出。两条概率路径的微小差异进入 `(p-one_hot) @ W` 后，在类梯度归一化中被放大，最终 4/4096 个 `delta` 元素超过原始容差。另有一个可独立隔离的次要差异：在紧凑类子集与完整零填充张量上执行 L2 norm，得到不同的浮点归约结果。

这不是仅根据“误差小”作出的推断：C 对照单独对齐概率计算后，概率、未归一化梯度和类别梯度均与 B 逐位一致；D 对照单独对齐 norm 的输入形状后，仍然出现原来的 4 个超限元素；E 同时对齐两项后，六个阶段全部与 B 字节一致。FP64 中 A–B 的最终最大绝对误差降至 `3.3306690738754696e-16`。上述干预共同支持本批次的因果解释。

未发现本批次存在公式、类别索引、非有限值或参数更新导致的问题。**此结论不能外推为全部批次的正确性证明**：本批次恰好有 64 个不同类别，每类 1 个样本，未覆盖同类多样本时的 mean/backward 归约路径。CUDA 内核的具体选择及内部归约树未做 profiler 追踪，仍为 UNVERIFIED。

## FP64 的解释边界

FP64 的 E 在所有阶段仍与 B 字节一致，A 的误差降至约 `1e-16`，支持两条实现的数学表达式在此输入上相符，差异随计算精度变化。

但 FP32 B 相对 FP64 B 的 delta 最大误差仍为 `1.7113680088054473e-06`，按同一容差有 26 个超限元素；FP32 A 相对 FP64 B 最大差为 `1.204728528214627e-06`。因此“对齐 FP32 Autograd”与“更接近 FP64 值”是不同评价。FP64 对照仅用于解释数值路径，不能作为修改精度或宣告正式实验通过的依据。

## 最可能根因、未确定事项与最小建议

**最可能根因（在此批次已有直接对照支持）：** 独立 Softmax 与 CE 内部 LogSoftmax 的 FP32 概率差，通过高置信度样本的 `(p-y) @ W` 与较小类梯度范数放大，造成原门禁超限；norm 的归约形状是次要、可独立观测的舍入差异。类别 28 的目标概率 A/B 为 `0.9907432198524475` / `0.9907432794570923`，与上述传播分析一致。

**尚未确定：** 其他真实批次、其他种子和同类多样本时的数值等价性；其他 GPU/PyTorch 组合的结果；CUDA 内部准确归约树；缺失历史批次哈希的逐项重放认证。没有证据把本批次的问题归因为公式或索引错误，也没有以此否定所有其他输入存在问题的可能。

**建议的最小修复，尚未实施：** 用户审查后，仅考虑将生产解析梯度的概率路径对齐为 C 的 `F.log_softmax(logits, dim=1).exp()`，保持公式、norm、权重、alpha、ADVER_REG、FP32 和原容差不变。本批次 C 已在原门禁下通过；后续仍需在获得授权后验证真实批次及同类多样本场景，不能把此次只读 C/E 诊断称为 Smoke 已修复或正式训练已获准。
