==============================
C. 实现 run_factorial.py
==============================

在本目录新建 run_factorial.py。它必须提供：
- unit
- preflight
- prepare
- train --seed {124,125} --arm {RandomDonor,HighAffinityDonor,RandomDonor+MarginProtect,HighAffinityDonor+MarginProtect}
- report

实现尽量直接，复用已有 helper；不需要新框架、不需要复杂插件化、不需要额外依赖。

C1. 训练集 GAP bank / prototypes
- 用冻结 Stage-I checkpoint 和原 eval_transform，对原 LT TRAIN 子集全部图像计算 GAP-64。
- 可复用本地已有 balanced_clean_train_bank.npz，但只有在其 Stage-I SHA、标签、原始训练索引、shape、特征有限性全部通过验证后才可复用；否则在本实验 results/ 下重新计算。
- 不得访问验证集或 TEST 构建 prototypes。
- 对 head 类 ID 0..35 建立 L2-normalized TRAIN prototype。
- 保存 train bank/prototype provenance：Stage-I checkpoint SHA、train labels/index SHA、eval transform、bank SHA、class counts、TEST_used=false。
- 确认 backbone/BN 前后 state hash 完全相同。

C2. donor plan：固定、配对、只改尾类接收者
- 复用原 sampling_plan 的 receivers；保留原来的 receiver 数组、batch 顺序、10 epochs×N rows。
- 只对接收标签 y[receiver] >= 71 的 draw 替换 donor；其他 receiver 的 donor 必须与原 sampling_plan 完全相同。
- head donor classes 为 0..35，按 class count 降序切为6个 strata，每个stratum 6类。
- 每个 tail receiver draw 使用 clean TRAIN GAP 与 head prototypes 的 cosine affinity。
- 通过可复现 NumPy Generator 预先产生 u_stratum、u_class、u_instance。A/B 必须使用完全相同的三组随机数。
- 先以各 stratum 的 class-count 总和为概率抽 stratum；A 在该 stratum 中按训练数量比例抽 class；B 在同一 stratum 的 top-2 affinity class 中按训练数量比例抽 class。每个类内按 u_instance 均匀选真实 TRAIN donor index。
- C 的 donor index 必须逐项等于 A；D 的 donor index 必须逐项等于 B。A/B 每个 tail draw 的 stratum ID 必须逐项相同。
- 每个 seed、每个 epoch都预先固定 donor plan，保存 donor index、receiver index、donor label/class、stratum、affinity、uniform variates/hash。训练中不得按当前 FC 或 validation 重新选 donor。
- 记录 donor class count/stratum 分布，明确承认同一 stratum 内 A/B 的 class count 分布仍可能不同。不能声称 donor 频次完全相同。
- 检查所有 donor index 属于 LT TRAIN，donor_labels == chosen_donor_class，receiver/donor 不得越界。

C3. 原始 Low-VS mask 与 MarginProtect mask
- 每个 batch 使用原 online_masks(receiver, y[donor], gumbel) 生成原始 donor-conditioned VS 分数和 Low-VS mask。
- 对四个 arm，receiver augmentation、donor augmentation随机数、Gumbel、receiver IDs和原始在线VS分数必须成对。每个 arm 使用相同的 seed+300009 augmentation Generator 初始化，按相同batch顺序执行。
- A/B：尾类接收者使用原 Low-VS Bottom48 → Gumbel-random 16；非尾类全部按原规则。
- C/D：仅尾类接收者使用 margin protection；非尾类必须完全使用原 Low-VS mask。
- 必须从现有 online_masks 的实际 trace 取得原 Bottom48 candidate pool。如果 trace 未直接暴露候选池，检查原 online_policy.py 并用完全相同的 score/rank/tie/fallback 逻辑重建；用断言验证重建候选池产生的原始16-mask与 online_masks 返回的 Low-VS mask完全一致。不得改动原 helper。
- 对每个 tail receiver，使用 policy.channel_margin_delta：
  q_d=(W[y,d]-W[j*,d])*(GAP(donor)_d-GAP(receiver)_d)，j* 为当前 unfused receiver logits 的最强非真实类别。
- 在原 Bottom48 候选中保护 q_d 最小的16个通道，从剩余32个中用同一批原始 Gumbel 值选择16个。不要从所有64个非保护通道选；不得改变 Bottom48。
- 每个融合样本必须恰好替换16个完整8×8 feature maps。被选通道与 donor 逐位相等，未选通道与 receiver 逐位相等，label仍为 receiver label。
- q_d是固定当前竞争类别下的即时 margin 变化贡献，不得描述为语义重要性或泛化效用。

C4. 训练一致性与防护
- 每个 arm/seed 都从 base.fresh(seed) 得到完全相同的初始 FC；使用原 optimizer_for 和 scheduler。
- backbone所有参数、BN affine、running stats、num_batches_tracked都必须冻结并逐位不变。
- 只有100-way linear classifier可以更新，且更新后参数有限。
- 每组10 epochs×85 batch=850 optimizer.step；batch_size=128，最后一个batch允许按原数据集长度为95。
- 训练过程中保存每batch签名：receiver IDs/labels、donor IDs/labels、两组增强像素、冻结特征、原始VS scores hash、Gumbel hash、原始LowVS mask hash、新实际 mask hash、q/geometry summary。
- 由于 A/B 有意改变 tail donor index，不能要求四臂 donor hash 完全相同；正确要求是 receiver/augment random stream/Gumbel相同，A与C donor完全一致，B与D donor完全一致；A/B donor只允许在 tail receiver draws不同，非tail donor index逐项一致。
- 官方 TEST guard事件必须为0；验证只用现有 TRAIN holdout feature maps。
- 训练失败后写 FAILED_STOP.json 和日志，停止，不覆盖输出、不自动重跑。

C5. 在线几何诊断
在每个 batch optimizer.step 之前，对 tail receiver draws记录：
- clean receiver margin与最强竞争类别ID；
- fused与clean的固定 j* margin差、fused动态 margin差；
- fused CE - clean CE；
- clean margin > 0 但 fused margin <= 0 的比例；
- 16个被选通道的 q_d 之和；
- 保护集 q_d 均值/分位数、选中集 q_d 均值/分位数；
- donor affinity、stratum、donor class count。
几何统计只解释即时行为，不得当作最终收益或因果证明。
