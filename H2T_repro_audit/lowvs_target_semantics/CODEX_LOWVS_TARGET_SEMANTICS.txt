目标：完成一个严格配对的三臂实验。只改变尾类融合样本的监督目标，回答 donor-aware / first-crossed-competitor-aware target 是否比原始接收者硬标签更好。不要扩展成新框架，不做超参数扫描，不重训 Stage I。

==============================
A. 研究问题与三臂
==============================

先阅读本目录的 PROTOCOL.md、policy.py、test_policy.py。

A = HardRecipient：原始 LowVS-Full 融合特征 + 接收者硬标签。
B = DonorMixTarget：仅 y_receiver >= 71 时，target=0.75*one_hot(y_receiver)+0.25*one_hot(y_donor)。
C = FirstCrossedCompetitor：仅 y_receiver >= 71 时，用冻结 balanced cRT reference head 找 clean-to-fused GAP 路径上的 first-crossed competitor；若 clean reference 严格判对且发生交叉，target=0.75*one_hot(y_receiver)+0.25*one_hot(first_competitor)，否则 hard target。

三臂只改 target distribution。不能加 clean anchor、risk weighting、label smoothing 或额外损失。软目标 CE 每行概率和为 1，与硬标签 CE 保持相同损失尺度。

==============================
D. 实现 run_target_semantics.py
==============================

在 H2T_repro_audit/lowvs_target_semantics/ 新建 run_target_semantics.py。优先复用历史 helper；不重写训练框架。

CLI：
- unit
- preflight
- prepare
- train --seed {124,125} --arm {HardRecipient,DonorMixTarget,FirstCrossedCompetitor}
- report

D1. Unit / preflight
- 先运行本目录 policy tests；使用原实验 Python 环境。
- 检查数据集真实 TRAIN raw indices / 标签与原 LT 子集一致。
- 检查 Clean Stage-I SHA、reference head 来源、缓存来源、原 LowVS-Full donor/receiver plan、Gumbel 与 helper hashes。
- 安装官方 TEST guard 和历史文件只读保护。
- 任何必要来源缺失、hash 不一致、输出已存在或 guard 失败，停止；不跳过检查，不自动重建历史输入。

D2. 固定输入流
- 复用原 LowVS-Full 的 receiver/donor schedule；不要使用 lowvs_factorial 的 donor-affinity plan。
- 两个 seeds 内，三臂共享同一份 receiver IDs、donor IDs/labels、增强随机流、frozen feature maps、Gumbel、原始 online VS scores、原始 mask、fused feature maps。
- 每臂从 base.fresh(seed) 或已核实的等价 helper 得到相同初始 FC；使用原 optimizer_for 和 scheduler。Backbone、BN affine、running stats、num_batches_tracked 全部 eval 冻结，仅 trainable 100-way linear classifier 更新。
- 每个 seed 三臂的 input/mask signatures 必须逐 batch 完全一致。target signature 可以不同，梯度/后续 FC 状态可以不同。
- 训练10 epochs、每epoch85 steps、batch128；实际 optimizer.step 必须精确850。
- 不选择 best epoch；固定 epoch10 为主终点。

D3. 监督目标
- 对所有非尾类 receiver（label <71），三臂全部用 hard receiver target。
- HardRecipient：所有样本硬标签。
- DonorMixTarget：尾类 receiver 使用真实 donor label，target mass 固定0.25；donor 与 receiver 同类时自然退化为 hard target。
- FirstCrossedCompetitor：用 frozen balanced cRT reference head 对 clean receiver GAP 与 fused GAP 计算 logits；调用本目录 policy.first_crossed_competitor。只对尾类 receiver应用该 target。clean reference 未严格判对或没有 crossing 时，target 回退 hard receiver label。
- Stage-II classifier logits只由原 trainable head产生。balanced cRT reference绝不能参与Stage-II预测loss、梯度或优化器更新。
- 用 policy.build_target_distribution + policy.soft_target_cross_entropy。所有target行和为1；不可把 CE 项相加，不能改变梯度整体尺度。
- 日志记录每个 batch 的 tail draw 数、donor异类比例、B软目标实际激活率、C crossing率、first-crossed class计数、hard-target fallback率及 target/mask/input hashes。

D4. 首次跨界数值核验
- 用独立小型CPU测试核验 alpha=m0/(m0-m1)，并检查 reference clean strict correctness、竞争类排除、tie按class ID、endpoint crossing alpha=1、无crossing sentinel=-1。
- 使用真实 batch 做额外断言：如果 first_crossed_competitor 返回 j，clean margin必须严格正，fused margin(j)必须<=0，alpha在[0,1]，且没有其他有效竞争类拥有更小alpha。
- GAP(clean/fused)必须来自当前同一次增强/融合的特征张量，不得重新增强或缓存不同图像版本。
- 如果 reference classifier不是线性GAP head，或无法证明 feature/logit path linearity，则停止，不使用本公式。

- 不给两个 seed 的重复开发集评估做显著性检验，不使用test-selected best结果作主结论。

==============================
F. 执行顺序
==============================

所有命令逐条运行；上一条成功后才执行下一条。使用原实验 Python 环境，不要猜新的解释器路径。

1. python H2T_repro_audit/lowvs_target_semantics/run_target_semantics.py unit
2. python H2T_repro_audit/lowvs_target_semantics/run_target_semantics.py preflight
3. python H2T_repro_audit/lowvs_target_semantics/run_target_semantics.py prepare

然后逐条训练：
4. train --seed 124 --arm HardRecipient
5. train --seed 124 --arm DonorMixTarget
6. train --seed 124 --arm FirstCrossedCompetitor
7. train --seed 125 --arm HardRecipient
8. train --seed 125 --arm DonorMixTarget
9. train --seed 125 --arm FirstCrossedCompetitor

最后：
10. python H2T_repro_audit/lowvs_target_semantics/run_target_semantics.py report

每条命令必须确认 exit code 为0、状态文件为预期成功状态后再继续。不得并行跑臂，不得在失败后自动重跑。
