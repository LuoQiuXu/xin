## Scientific objective

Test whether tail-class feature perturbations generated from a TRAIN-only augmentation-induced subspace improve a frozen-feature long-tailed classifier, and whether projecting the perturbation toward the nearest Stage-I competing boundary adds value beyond random directions.

This is a controlled mechanism experiment, not a claim of novelty and not an official-test benchmark.

## Step 4 — Prepare frozen feature streams

Run:

~~~powershell
& 'D:\app\anaconda\envs\pytorch\python.exe' -B -u H2T_repro_audit/structured_feature_perturbation_20261105/run_experiment.py prepare
~~~

This extracts frozen 64-D GAP features from the existing Clean Stage-I backbone. It creates a separate feature cache for Stage-II seeds 42, 43, and 44. Within each seed:

- each epoch uses class-balanced receiver sampling;
- each donor epoch is a permutation of the full 10,847-image LT training set;
- original train transforms are applied with a private deterministic augmentation RNG;
- the receiver and donor feature streams are frozen and reused identically by all five arms;
- the donor bank is aligned by original training-image index;
- the first two donor-view epochs provide paired augmentation differences for the class-conditional covariance subspaces;
- the fixed Stage-I classifier and the learned subspaces produce per-receiver boundary directions and norm budgets.

The script writes caches under the ignored feature_cache/ directory. It writes a tracked prepare_manifest.json with source hashes, cache hashes, class counts, subspace diagnostics, boundary eligibility, and configuration.

The extraction uses batch size 128 and the frozen backbone in eval mode. If CUDA OOM occurs, do not silently change the protocol or continue with partial caches. Record the failure and report it. A smaller extraction batch may be introduced only as a code-level memory-safe implementation change that preserves the same sample order, augmentation RNG stream, features, and final 128-example Stage-II batch schedule; verify the resulting feature hashes and document the change.

## Step 8 — Scientific interpretation to include in the handoff

Answer these questions from the actual outputs:

1. Does Subspace-Boundary improve Few/Tail over cRT and H2T-pooled?
2. Does it improve Few/Tail over norm-matched Gaussian?
3. Does it improve Few/Tail over norm-matched Subspace-Random?
4. Does the effect preserve Many/Head accuracy?
5. Does Tail-to-Head error fall without a compensating Head-to-Tail increase?
6. What fraction of tail receiver draws is boundary-eligible? Is the projection alignment often too weak?
7. Are the perturbations actually norm matched and subspace constrained?
8. Are the per-seed directions consistent, or does one seed drive the mean?
9. Does the result support the proposed mechanism, reject it, or remain inconclusive?

Do not call the approach successful based on Overall accuracy alone. Do not infer improved generalization from an algebraic margin reduction or from the instantaneous Stage-I classifier. The validation set is a reused TRAIN holdout and official TEST has not been evaluated.

Decision rule:
- If Subspace-Boundary beats both Gaussian and Subspace-Random on Few/Tail while avoiding a material Many/Head regression, recommend a separately pre-registered confirmation on a new dataset or a previously untouched test protocol.
- If Subspace-Random matches or beats Subspace-Boundary, do not add more boundary gates; boundary guidance has not shown incremental value.
- If Gaussian matches the structured arms, the subspace has not shown incremental value.
- If all generated arms fail against cRT and H2T-pooled, stop this candidate rather than adding more modules.
