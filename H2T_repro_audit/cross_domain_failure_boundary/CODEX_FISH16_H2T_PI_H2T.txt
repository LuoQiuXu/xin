IMPLEMENTATION DESIGN
Create a clean, self-contained runner and unit tests. Reuse original method operations where practical, but keep old upstream code immutable.

A. Backbone
- Use H2T's ResNet50_FE from H2T_official_clean/H2T-main/models/resnet.py with pretrained=True.
- Return the 2048-channel feature map after layer4 (before GAP).
- Plain branch uses the backbone unchanged.
- PIF branch wraps the SAME ResNet50_FE initialization and inserts the existing PI-H2T PermutationInvariantFusion after layer4 and before GAP.
- Both branches must load identical ImageNet-pretrained ResNet50 weights; PIF has only the existing two shared PIF parameters.
- Do not substitute ResNet32 or an unrelated backbone.
- Record the pretrained weight source and SHA256. If pretrained weights are not cached and cannot be obtained, STOP; do not silently switch to random initialization.

B. Stage-I
- Train Plain and PIF branches separately but with identical data split, initialization source, transforms, seed, optimizer, LR schedule, batch, epoch count, and MixUp.
- 224x224 input.
- Train transform: RandomResizedCrop(224), RandomHorizontalFlip, ColorJitter(0.4), ToTensor, ImageNet normalization.
- Eval transform: Resize(256), CenterCrop(224), ToTensor, ImageNet normalization.
- CE + MixUp alpha=1.0.
- Pilot: seed=42, 90 epochs, SGD lr=0.01, momentum=0.9, weight_decay=1e-4, 5-epoch warmup + cosine.
- Save best checkpoint by validation only; keep current/final checkpoint too.
- No test-set evaluation during training.

C. Stage-II six conditions (see protocol table)
1. A0 Plain Stage-I evaluation.
2. A1 Plain cRT, no fusion.
3. A2 H2T, rho=0.25.
4. B0 PIF Stage-I evaluation.
5. B1 PIF-cRT, no fusion.
6. B2 PI-H2TF, paper_theoretical_bounds, ratio_detach=True.
- Stage-II 10 epochs, SGD lr=0.01, momentum=0.9, weight_decay=5e-4, cosine.
- All Stage-II conditions freeze extractor parameters AND BN running statistics (eval mode); optimize classifier only. This is the primary matched-BN comparison. Clearly document that the original H2T config uses shift_bn=True; do not silently claim exact reproduction of that BN behavior.
- cRT, H2T, and PI-H2T use identical class-balanced recipient schedules.
- For H2T and PI-H2T, use the same pre-generated donor index pairs for each epoch: donors sampled from the natural long-tailed train distribution with replacement. Do not force donors to be head-only, different-class, or different-track. Log those relationships.
- H2T must preserve the original random channel replacement semantics and rho=0.25; no new channel selector.
- PI-H2TF must use the existing formula: GAP; cosine between recipient feature and current classifier weight for recipient label; r=(1-cosine)/2; fused=r*recipient+(1-r)*donor; ratio_detach=True.
- PIF-only cRT is required to separate the PIF representation contribution from H2TF fusion.

D. Evaluation
- Use validation for model selection and test exactly once after checkpoint selection.
- Report image-level Overall, Macro, Head/Medium/Tail, per-class, worst-class, confusion matrix.
- Head/Medium/Tail are training-frequency tertiles with 6/5/5 classes, not CIFAR paper's absolute thresholds.
- Also report trajectory-level mean-logit accuracy.
- Bootstrap by test trajectories (not independent images), >=1000 resamples, for Macro and Tail confidence intervals.
- Save test logits and sample IDs.
- Compare fused model against matched cRT on identical test images: correct->wrong, wrong->correct, target-margin delta, per-class delta.
- Log H2T selected channel IDs/counts, PI r and (1-r) distributions by class, recipient/donor class, donor frequency group, same-class and same-track pair rates.
- Show test image count and independent test-trajectory count per class. Explicitly warn that some tail classes have only 3 test tracks.
