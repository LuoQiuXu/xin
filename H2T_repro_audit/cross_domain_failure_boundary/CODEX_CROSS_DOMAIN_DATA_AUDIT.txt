请先阅读：
- H2T_repro_audit/cross_domain_failure_boundary/SCIENTIFIC_PROTOCOL.md

我们的核心目标是寻找 H2T / PI-H2T 在不同视觉领域的适用边界。当前这一轮是正式跨领域训练前的数据有效性门禁，不是继续拆解 H2T 的融合模块，也不是方法性能实验。

候选数据：
1. ISIC 2019：医学皮肤病变分类，使用 lesion_id 防止同一病灶跨集合。
2. Fish4Knowledge FRGT：水下鱼类分类，使用 tracking ID 防止同一鱼类轨迹跨集合。

三、执行顺序

A. CPU 契约测试

在仓库根目录运行：

python -m unittest discover -s H2T_repro_audit/cross_domain_failure_boundary -p "test_*.py" -v

要求全部通过。若失败，先修复本目录内代码并重新运行测试，不得跳过失败测试。

B. 语法检查

python -m py_compile H2T_repro_audit/cross_domain_failure_boundary/audit_external_domains.py

C. ISIC 2019 审计

确认本地目录包含完整训练图像、Training_Metadata.csv 和 Training_GroundTruth.csv。运行：

python H2T_repro_audit/cross_domain_failure_boundary/audit_external_domains.py --dataset isic2019 --images-root "<本地ISIC训练图像目录>" --metadata-csv "<Training_Metadata.csv>" --ground-truth-csv "<Training_GroundTruth.csv>" --output-dir "<仓库外目录>/isic2019"

D. Fish4Knowledge 审计

确认本地目录已解压官方23个 fish 图像类别包，目录结构能从 fish_01 或 01.Species 识别类别；只放图像，不要放 mask 包。运行：

python H2T_repro_audit/cross_domain_failure_boundary/audit_external_domains.py --dataset fish4knowledge --images-root "<本地Fish4Knowledge图像目录>" --output-dir "<仓库外目录>/fish4knowledge"

如果当前解压结构不符合脚本要求，不要猜类别或手工编造 tracking ID。先报告真实目录结构和文件名样例，再决定是否增加一个明确的路径适配器。

四、严格的数据有效性要求

1. ISIC：使用官方8类one-hot标签，按 lesion_id 分组；缺失 lesion_id 的样本必须单独统计，不能伪造 lesion ID。
2. Fish4Knowledge：按官方 tracking ID 分组，同一 tracking ID 必须始终在同一个 split。
3. 两个数据集都要检查图像能否解码、SHA256、完全重复图像、类别计数和独立 group 数。
4. 不能随机按图片划分训练/验证/测试集。
5. Fish4Knowledge 全23类必须保留在审计结果中。只有满足至少9条训练轨迹、3条验证轨迹和3条独立测试轨迹的类别，才能进入 primary manifest。其余类别列明具体原因，不得静默删除。
6. ISIC 2019 必须有8个类别全部满足预先规定的独立组数量门槛，否则该数据集不能进入8类确认性训练。
7. 输出中的 Head / Medium / Tail 是各数据集训练类频的三分位分组，不得冒充 H2T 原论文 CIFAR Many / Medium / Few 的绝对阈值。
8. 如果官方发布图像数量、类别数量或 Fish4Knowledge 轨迹数量不匹配，状态必须是 NO-GO，先核对数据版本，不能通过改阈值强行放行。
