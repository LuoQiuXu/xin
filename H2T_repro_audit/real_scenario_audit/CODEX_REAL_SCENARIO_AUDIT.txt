3. SCREEN B: TEST-TIME CLASS-PRIOR SHIFT (REQUIRED; NO TRAINING)
============================================================

Research question:
Does the relative ranking/gain of the available H2T variants versus a matched baseline depend strongly on the evaluation class prior? This is a prior-sensitivity screen, not a test-time adaptation experiment.

Use the best-supported matched comparison among the existing frozen models. Prefer in this order:
A. cRT vs Original-H2T, if both have predictions from the same checkpoint backbone, split, and protocol;
B. Uniform-PerSample vs Low-VS, if A cannot be constructed fairly;
C. another matched pair only if its provenance is clearly documented.
Do not combine results from different backbones/seeds and call them paired. If multiple seeds have matching predictions, report per-seed results first and summarize the paired differences.

Use existing TRAIN-held-out validation predictions as the primary source. Some historical validation splits cover classes 1..99 only and omit class 0. If so:
- explicitly report the missing class;
- renormalize all target priors over the observed classes only;
- label all resulting values “99-class partial prior audit”;
- do not claim full CIFAR-100 expected accuracy.
Do not use official-test predictions to select a method or tune anything.

Compute class-wise top-1 accuracy from per-sample predictions, if available. Evaluate expected top-1 accuracy under these fixed priors:
1. Uniform prior over observed classes.
2. Forward long-tail prior: the same geometric class-frequency schedule as CIFAR-100-LT IF=100, restricted and renormalized over observed classes.
3. Reverse long-tail prior: reverse the class-frequency schedule, then restrict and renormalize over observed classes.
4. Optional IF=10 forward prior only if it can be added with trivial code; do not let this delay the main audit.

For each model and prior, report:
- expected top-1 accuracy = sum_c p_target(c) * per_class_accuracy(c);
- Macro accuracy (uniform class weighting);
- paired method delta in percentage points under each prior;
- which classes drive the delta (compact per-class CSV);
- whether the sign of the method delta changes across priors.

If paired per-sample predictions are available, calculate a deterministic paired bootstrap 95% interval for the method difference by resampling images WITHIN each observed class and recomputing the prior-weighted difference. Use a fixed, documented bootstrap seed and at least 2,000 replicates. Do not treat epochs as independent samples. If only per-class aggregate accuracy is available, skip the bootstrap and state why.

Use the training class-count schedule only to define the specified counterfactual prior; never use test labels to estimate or tune a target prior. Clearly state that this reweighting assumes class-conditional accuracy remains fixed and changes only p(y). It does not simulate covariate shift, retrain the model, or demonstrate adaptation.

Interpretation rule:
- A sign reversal or a large, reproducible reduction of the candidate's advantage under a predeclared prior is a reason to investigate prior sensitivity further, not proof of universal failure.
- If no reversal appears, report that the tested prior shifts did not reveal a ranking reversal. Do not invent a failure.

4. SCREEN C: OOD REJECTION (OPTIONAL, ONLY IF VALID DATA EXISTS)
============================================================

Run this only if a legitimate OOD image dataset is already available locally and the existing frozen models can be evaluated with the correct CIFAR-100 preprocessing. Prefer SVHN if it is already cached; otherwise use one already-available, clearly described OOD dataset. Do not download or synthesize a dataset for this task. If none exists, emit status “SKIPPED_NO_LOCAL_OOD_DATA” and explain what is needed for a future run.

Use the same held-out ID validation images as the ID score source. Run inference only; no training or threshold tuning on OOD data.

For each matched model, compute:
- MSP (maximum softmax probability);
- Energy score, with the exact formula and temperature documented;
- AUROC (higher is better);
- AUPR-Out (higher is better);
- FPR95 (lower is better; threshold chosen to retain 95% ID TPR using ID validation scores only);
- fraction of OOD images whose argmax is in the predeclared tail-class set, reported as a diagnostic rather than an OOD metric.

Use the same ID/OOD examples and transforms across compared models. Validate tensor shape, class dimension, finite logits, and score direction before computing metrics. Report class overlap/domain caveats. CIFAR-10 should not automatically be called a clean OOD set because some semantics overlap CIFAR-100.

This OOD screen is secondary: H2T is a closed-set long-tailed classifier, so weaker OOD rejection alone does not establish a defect in its intended setting. Do not broaden the paper claim based only on this audit.
